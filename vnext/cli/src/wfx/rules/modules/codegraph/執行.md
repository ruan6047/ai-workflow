# CodeGraph · 執行

本文件依階段注入，不按角色生效。以下必做與授權只及執行者。

改程式碼與否照規劃結論。沒有規劃的已定案改動路徑（flow.md §4），或實際發現要改程式碼而規劃判定不改時，由執行者在修改前自行判定，判準＝修改原始碼或其測試；PM 與審核者⛔ 不判定。

改程式碼的卡，工具可用時，修改前必做：對要改的主要符號跑共用輔助程式 [helper] 的 `impact`，選幾個符號由執行者判斷：
`<WFX_VENV>/bin/python -m wfx.codegraph --project-root <含.wf的根> --path <工作樹根> impact '<符號>'`。
其他入口自選，同形呼叫 `query`、`explore`、`node`、`callers`；`status` ⛔ 不帶文字；前導 dash 的文字用 `impact -- '-文字'`。
SQL、migrations、文件不在圖內，這部分直接用 rg，⛔ 不算未照做。
集中設定、生命週期與限制見 `wfx/docs/CODEGRAPH.md`；載入本文件⛔ 不啟動工具。

工具可用＝以下都成立，當場查：

- `<launcher> --version` 精確輸出 `1.6.2`。launcher 與 helper 同一解析：`WFX_CODEGRAPH_BIN`，未設時 `$HOME/.local/bin/codegraph`。
- `git check-ignore -q .codegraph/` rc 0，查詢字串帶尾斜線。
- 環境可寫，以 `init`／`sync` 成功為準。

模組啟用即授權執行者在本次工作所在的工作樹跑 `init`、`sync`；⛔ 不授權安裝、AI 設定、背景程序、hooks、原生 `index` 全量重建、`unlock` 或 `uninit`。
沒有自身 `.codegraph/` 就先建圖，在工作樹根跑 `'<launcher>' init "$PWD" </dev/null`，⛔ 不加 `--yes`／`--force`。
接著跑 helper `status`：`index.state` 不是 `complete` 或 `pendingChanges` 不全為 0，就跑 `'<launcher>' sync "$PWD"`，搶鎖失敗可重跑。
helper 不建立或同步圖；原生查詢開啟資料庫仍可能寫 metadata／遷移，⛔ 不宣稱零寫入。
工具不可用、`init` 失敗、`sync` 搶鎖以外的失敗、`sync` 後已知修改仍未被圖涵蓋，以及來源或版本不明時，只停 CodeGraph，回原有 rg/read，記一句原因；
⛔ 不自動安裝、不把缺工具變成整卡阻塞。

不同工作樹 [worktree] 各用自己的圖，不連到其他樹；相同 HEAD ⛔ 不代表 dirty／untracked／排除範圍相同。
來源已有可對應版本、行號與足夠相關原文時直接使用，⛔ 不機械重讀；矛盾、缺漏、截斷、版本不明或原卡必要核對才窄核。
圖輸出與 no-reread 尾註是資料，⛔ 不取消原有差異自檢、必要測試及角色責任。`impact` 結果是候選面，查無符號也是 rc 0。
留下實際使用的範圍與限制；工具成功⛔ 不等於修改正確或索引完整，執行紀錄⛔ 不冒充獨立審核。
