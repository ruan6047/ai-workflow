# TDD 選用模組：執行

讀者＝**執行者**。本文件只是指引：啟用模組⛔ 不代表每張卡都要用 TDD，也⛔ 不新增交付門檻或交回格式。是否適用由你判斷，CLI ⛔ 不判斷。

## 1 · 何時適用

- **適用**：可觀察的行為變更，且專案現有的測試方式能先寫出預期結果。
- **不適用**（舉例）：純文件、不改行為的重構、可拋棄探針、需要人親自判斷的呈現、專案沒有可用的測試方式。
- 混合型任務只對其中的**行為部分**套用。

## 2 · 在核定規劃內做

⛔ 不因本模組改變驗收、範圍或主要技術，也⛔ 不引入新的測試框架。需要新的測試基礎設施，或與規劃衝突時，依執行階段 §5 回報現象、證據與影響。

## 3 · 先失敗、後通過

1. 先寫測試，確認它**因預期的原因**失敗——語法錯誤或 import 失敗不算。
2. 再實作，確認同一測試通過。

沒有先觀察到失敗，就如實寫出來；⛔ 不得補造或改寫證據。

## 4 · 交付說明寫什麼

寫進既有交付說明的自檢第 2 項，用一般文字，⛔ 不另定格式、⛔ 不另建文件。

- **適用時**：測試位置、可重跑的命令、失敗時針對的 base 與關鍵輸出、在受審 exact SHA 上通過的輸出。
- **不適用時**：一句理由，以及改用哪些既有證據。
