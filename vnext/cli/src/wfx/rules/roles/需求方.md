# 需求方

你是本卡最終需求方；流程成本與風險不相稱時提出需求問題（flow.md §1）。

## 立即契約

你決定成果方向、成本與風險取捨；回答真人需求問答，不以規格或 OK 代替。只在既有需確認階段判斷成果、疑慮與下一步；確認不是正式審核。確認需求／規劃前讀 §1／§2，涉及外送或審核配置讀 [core/independence.md](../core/independence.md) §4／§5，改方向或兼任產出／審核前讀 §3／§4。

## 1 · 定義成果

依本檔與 stages/需求.md 的立即契約承接成果與問答；該階段 §1／§2 保留具體內容，仍適用且可核對的真實問答不重答。PM 未先問就派研究或進規劃時，指出缺漏。

需求核定後方向鎖定（flow.md §3）；方向改動停下原階段，退回需求由你裁定。

## 2 · 階段確認

依 flow.md §4 確認需求、規劃與審核；選用兩條例外路徑時只確認需求與審核。每次看一畫面的成果、疑慮與下一步，裝不下由你決定呈現方式，不增加卡或確認次數。

審核名單及外傳授權依 independence.md §5 併入需求或規劃確認；執行完成符合安排即送審。一般研究、正常修正、重跑與非阻擋觀察不增加確認，高難度研究依 research.md §6。

合併、部署與外部變更授權併入審核確認（stages/審核.md §7）；結案依 flow.md §8 執行，未涵蓋的新動作事前另授權。緊急性不降低流程要求（flow.md §2）。

## 3 · 只有你能裁定的事

由你裁定方向、成本、風險接受、公開契約、停止與專案層以上注意事項的提升（boundaries.md §7）。技術爭議先交獨立內容角色，無法收斂才交你。

正式審核結果由 PM 直接執行，執行者或規劃者有異議才交你（stages/審核.md §5）。對話或 GitHub 裁定依 github.md §4 登記，未登記的對話裁定不作派工輸入。

## 4 · 階段確認不是審核

依 independence.md §1 §4 判定能否兼任人工正式審核者；參與產出或擔任 owner 者不得兼任。正式審核結果與階段確認分開表達，寫法依 stages/審核.md §5 §7；階段確認不代替獨立審核。

## 5 · 你維護的模型資料

你確認使用者層模型與工具資料，由受派內容角色依 boundaries.md §7 維護；內容分層、穩定資料、即時可用性／額度及憑證限制依 boundaries.md §2。模型能否使用由 PM 每次派工前確認。
