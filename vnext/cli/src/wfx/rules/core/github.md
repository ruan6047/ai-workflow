# GitHub 呈現

一個概念只有一個權威居所；GitHub 畫面⛔ 不重複保存同一狀態。

## 1 · Issue body 五章節

body ＝五個固定章節標題＋自由文字：

1. `## 需求`（要解決的問題／主要成果／最終需求方；相連任務以 issue 連結標明）
2. `## 限制與非目標`
3. `## 驗收`
4. `## 風險與假設`
5. `## 裁定紀錄`（只放留言連結索引）

CLI 只確認「標題在且其下非空」，⛔ 不解析散文語意、⛔ 不要求大型 JSON、⛔ 不用任何卡面 JSON 格式。

## 2 · 七個核心概念（唯一來源）

| 概念 | 落地 | 值 |
|---|---|---|
| 狀態 | Project **內建 `Status` 欄位**（唯一狀態欄） | 六值，見 values.md |
| 階段 | 自訂 SingleSelect | 5 值 |
| owner | 自訂 text | 該卡唯一 owner |
| 風險 | 自訂 SingleSelect | 3 值 |
| 緊急性 | 自訂 SingleSelect | 3 值 |
| 期限 | 自訂 date | — |
| Resource | 自訂 text | 見 §6 |

**自訂欄位恰六個**；狀態由內建 `Status` 承載——平台允許改名為 `狀態` 時改名後仍是同一欄，不允許時沿用 `Status` 欄名（`Status` ＝狀態）。**⛔ 不得另建自訂狀態欄**；預設 view 以 `Status` 分欄；其餘內建欄位列為不使用、不寫入。

Project fields 是階段、狀態、owner、風險、緊急性、期限及當前資源狀態的**唯一來源**。模組⛔ 不得新增／刪除／改義／改值域這七個概念。

**⛔ 不雙寫**：期限、風險、緊急性、資源⛔ 不進 body；模型可用性住使用者層，⛔ 不進 body、⛔ 不進欄位；工作包清單住該卡**已貼出的規劃階段完成留言**，⛔ 不開子 Issue、⛔ 不加欄位、⛔ 不建完成度計數器。

## 3 · 留言只有四類

**階段完成卡、需求方裁定、阻塞／解除、結案。** 退回事件的留言歸入前兩類之一。

⛔ 不貼移動紀錄、欄位 hash、長篇 CLI 輸出或重複狀態；工作包完成⛔ 不發留言。

**階段確認留言只登記裁定者、時間與結論，⛔ 不重貼完整內容**；技術證據保存在既有 PR、commit 或 CI artifact 等持久位置，⛔ 不搬進留言。

## 4 · 裁定以留言為權威

`## 裁定紀錄` 只是索引，**裁定的權威居所是留言**。需求方可在對話或 GitHub 裁定；對話中的裁定由 PM 忠實登記裁定者、內容與時間，⛔ 不得擴張原意。

派工內容必須能由框架規則、使用者層資料、Issue body、七個核心概念、已核定階段卡片與 `.wf/` 重新產生；⛔ 不依賴 PM 私有對話記憶——未登記為留言的對話裁定⛔ 不得作為派工輸入。

## 5 · 開卡與關卡＝PM 的平台協調操作

以 `gh issue create --body-file <五章節檔>`、`gh project item-add`、`gh issue close` 執行。⛔ 不經 GitHub UI 套用舊的 issue 模板（舊卡片格式⛔ 不治理本框架）。

這些操作⛔ 不算框架外人工補救、⛔ 不進 CLI 的寫入契約——CLI ⛔ 無開卡／關卡／改 body 能力。

## 6 · Resource 與資源租用

任何角色若會改動共享的 DB、VPS、GPU、staging、測試帳號或其他資源，都必須先取得**資源租用**；租用至少包含任務、角色、用途、存取模式及釋放條件。租用只代表協作許可，**不是技術隔離證據**。

釋放前確認相關程序停止及必要恢復完成。狀態不明時可以釋放協作占用，但必須標示「狀態未知」，下一位使用者⛔ 不得直接寫入。既有資源⛔ 不因租用結束而自動刪除。

`Resource` 欄位只保存**當前**占用者／用途／存取模式／釋放條件，⛔ 不存租用歷史、⛔ 不建新狀態機。**憑證⛔ 不得存入任務卡或框架設定。**

## 7 · 寫入基準

- **正常路徑＝`facts` → `write --expect-updated-at <ts>`，一次成功。** `facts` 輸出 Project item 與 Issue **各自的 `updatedAt`**＝寫入基準：改欄位帶 item 的、貼留言帶 Issue 的。⛔ 不得把「每次 mutation 先失敗一次再重送」寫成正常路徑。
- **缺 `--expect-updated-at` ⇒ 拒絕寫入**（rc≠0、遠端零 mutation），輸出被修改物件的當下值與當下基準。這是**負控與安全網**，用途是擋掉「跳過確認直接寫」，⛔ 不是預期會頻繁走到的路徑。
- **基準不符 ⇒ 同樣拒寫**，輸出當下值與當下基準；呼叫者重新確認後以新基準重送。
- **`--dry-run` 零遠端 mutation，⛔ 不要求基準**；有提供基準則執行相同比對並印出 would-write 與比對結果，未提供則只印 would-write 並標明「未做基準比對」。
- **⛔ 不宣稱基準讀取與寫入之間具有原子性**：基準只縮小視窗，不構成鎖。⛔ 無鎖定服務、⛔ 無通用寫入帳本、⛔ 無續作或復原契約。
