# 執行階段

## 1 核心目標
產出物＝分支 SHA＋交付報告＋自測證據。進入＝規劃完成（T0／T1 直通）。⚠️ iteration 唯一遞增處。離開＝交付報告過 ④ → 審核／待辦。

## 2 狀態與轉移
通用 7，不加不減。

## 3 階段內流程
② 派工包（規格＋三層注意事項＋13 族清冊＋上一輪退回理由＋信封模型行）。③ 執行者推分支＋交回交付報告——⭐ 報告是 ③ 的一部分：只推 commit 沒報告＝仍在進行中。④ PM 對報告完整性（失誤登記／未驗清單逐項、清冊格數）。⑤ 過＝審核／待辦。失聯出口＝新 iteration 重做，或他人出「複驗報告」（逐字標⛔ 非自評）。

## 4 各角色
| 角色 | 做 | ⛔ 不做 |

| 執行者 | 實作、自測、自評 | 不 merge；不自審；遇授權缺口停下寫阻塞發現，不擴權不開卡 |
| PM | ② 派工包；④ 報告完整性 | 不判碼對錯；不代寫執行者自評 |
| 需求方 | 裁授權缺口 | — |

## 5 注意事項（12）
1. worktree 內 Edit/Write/server 路徑指向 worktree，⛔ 不指 main checkout
2. （並行共用 checkout 時）逐檔 add、⛔ 禁 add docs/；SHA 用 rev-parse ⛔ 不手打
3. ⛔ 不截斷輸出（| tail 吃掉 rc 與守衛裁決）
4. rc=0 ⛔ 不等於成功——看被改變的狀態
5. 宣告成功前先核那次執行的識別碼
6. 驗證器要 import ⛔ 不重打
7. 複驗要用會通過的樣本
8. 算術上不可能的結果最先響
9. 刻意行為就地留註解（刻意／為什麼／⛔ 不得推出什麼）
10. 修過期引用的動作最容易留下新的過期引用
11. 交付物寫事實⛔ 不寫狀態（狀態寫查詢方法）
12. 失誤登記與未驗清單逐項轉錄，⛔ 不摘要⛔ 不加緩和語；「全部」附 artifact 窮舉證據
